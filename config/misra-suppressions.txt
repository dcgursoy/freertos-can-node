// MISRA C:2012 deviations for lib/ and app/, in cppcheck suppression syntax.
// Each entry is explained in docs/misra-deviations.md. Keep the two files in step.

// Rule 1.4 (emergent language features): the project is written in C11 on purpose and uses
// <stdatomic.h> for its lock-free ring and _Noreturn for the reset functions. Rule 1.4 comes
// from Amendment 2, which predates MISRA's own guidance for C11 (MISRA C:2023 permits both).
misra-c2012-1.4

// Advisory rule 15.5 (single point of exit): not adopted project-wide. Early returns are
// used for argument checks where they make a function shorter and clearer.
misra-c2012-15.5

// Advisory rule 8.7 (no external linkage when used in one unit only): the modules under lib/
// are libraries; their public functions are called by other modules and by the unit tests,
// which the analysis of one program configuration cannot see.
misra-c2012-8.7

// Advisory rule 8.9 (define an object at block scope if only one function uses it): the
// statically allocated kernel objects and buffers of a module are declared together at file
// scope, so the module's memory budget can be read in one place.
misra-c2012-8.9

// Advisory rule 11.5 (conversion from pointer to void) in the generic ring only: it stores
// elements of a caller-chosen type and, like memcpy, takes them as void pointers.
misra-c2012-11.5:*/lib/ring/spsc_ring.c

// Required rule 17.1 and rule 21.6 in the logging front end only: a printf-style log call
// needs <stdarg.h> and vsnprintf. No other file may use them.
misra-c2012-17.1:*/lib/log/log.c
misra-c2012-21.6:*/lib/log/log.c
